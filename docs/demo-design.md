# DataMind AI：首版 Demo 设计

## 1. 演示要证明什么

用户不写 SQL，也能从自己上传的表格得到可核对的分析结果。所有数值来自实际查询；每张图与结果表共用同一份查询结果。AI 负责理解问题、调用工具和解释，不充当计算器。

首版只做单机、单用户、一个当前数据集的完整闭环。每次提问独立分析；不承诺“那上个月呢”这种依赖上下文的问题。界面可保留本次会话的结果卡片，刷新后不保留。

## 2. 一个工作台完成全部操作

桌面布局采用两栏，避免用户在多个页面间切换：

```text
┌ DataMind AI ───────────────────── 模型连接状态 ┐
│ 数据区 240px │      分析主区（自适应）       │
│             │                               │
│ 上传表格     │  用一句话，读懂你的数据         │
│ 使用示例数据 │  [地区排名] [月度趋势]          │
│             │                               │
│ sales.csv   │  用户：哪个地区销售额最高？     │
│ 24 行 / 4 列│  状态：正在执行查询…           │
│             │                               │
│ 字段与类型   │  华东最高，合计 128 万元       │
│ month       │  [图表] [结果数据] [SQL依据]   │
│ region      │  ███████ 华东                 │
│ sales       │  █████   华南                 │
│ orders      │  ████    华北                 │
│             │                               │
│ [数据预览]   │  [输入你的问题……] [分析]       │
└─────────────┴───────────────────────────────┘
```

上图为两栏主布局；结果卡片内划分“结论、图表、依据”三个区域，不新增独立右侧面板。

视觉方向：浅灰背景、白色卡片、深蓝主色，少量青绿色突出完成状态。优先保证表格、单位、坐标轴可读；不做装饰性大屏。窄屏时数据区收起为抽屉。

关键交互：

- 空状态提供“上传 CSV / XLSX”和“使用示例数据”两个入口，并提示数据分析用途。
- 上传后显示文件名、行列数、字段类型及前 20 行预览；Excel 首版只读取第一个工作表，并明确显示工作表名。
- 提问按钮在数据未就绪、问题为空、任务执行中时禁用；错误后允许修改问题再试。
- 状态只展示真实事件：读取字段、请求模型、执行查询、生成解读、完成。首版普通 HTTP 请求只保证显示“分析中”，不能用计时动画伪装详细执行进度；详细步骤可完成后作为执行记录展示。
- 结果卡片包含简明结论、柱状图或折线图、结果表、可展开的 SQL 和口径说明。
- 更换数据集时明确开始新会话，清空旧结果，防止跨文件误读。
- 模型不可用时明确报错。无密钥可体验上传、预览及标注为“预设 SQL”的示例查询，不宣称完成 AI 分析。

## 3. 首版功能边界

| 必须交付 | 暂缓 |
| --- | --- |
| UTF-8 CSV、XLSX 上传与数据预览 | 多工作表合并、跨文件关联、Parquet |
| 字段类型、行数、缺失值数量 | 自动修复脏数据、复杂清洗 |
| 单表筛选、分组聚合、排序、Top N | 任意 Python 代码执行、预测和因果归因 |
| 一次真实 SQL 工具调用及结果解读 | 多 Agent、长期记忆、复杂 Planner |
| 柱状图、折线图、结果表、SQL 依据 | 自由拖拽 Dashboard、导出报告 |
| 明确的错误、超时、空结果提示 | 登录、权限、多人协作、历史持久化 |

默认限制作为可调整的后端配置：文件 10 MB、100,000 行、100 列；预览 20 行、分析结果最多 500 行、查询超时 10 秒、整次分析超时 60 秒。超限直接解释原因，不静默截断源数据。

## 4. 数据流与最小实现

```text
Vue 上传文件
  → FastAPI 校验格式、大小及数据结构
  → CSV / openpyxl 读取 XLSX → Polars 数据检查
  → 写入 Docker 中的 MySQL 独立数据表
  → 返回 dataset_id、字段、预览

用户问题 + dataset_id
  → 后端读取字段及类型
  → LLM 请求 run_sql 工具（只能查询 data 表）
  → 后端校验并在受限连接中执行 SQL
  → 实际结果交给 LLM 生成简短解释
  → 后端验证 ChartSpec 的字段与结果表一致
  → Vue 展示结果，ECharts 渲染图表
```

传给外部模型的内容默认包括问题、字段名称/类型和聚合查询结果；不默认发送完整原始文件。界面应说明这一点，演示统一使用合成数据。

保持已确定的技术路线。Vue Router、Pinia、Axios 可按团队约定接入，但首版不为每块页面建立独立状态层。NumPy、SciPy、scikit-learn、Pandas 在出现实际算法需求时再加入；第一版不安装全部数据科学生态。

建议实现目录，当前不创建空目录或空模块：

```text
frontend/src/
  App.vue                 工作台与会话状态
  components/
    DatasetPanel.vue      上传、字段、预览
    AnalysisResult.vue    结论、结果表、SQL
    ChartRenderer.vue     ChartSpec → ECharts
  api.ts                  API 请求
  types.ts                接口类型
backend/app/
  main.py                 API 路由与错误响应
  datasets.py             导入、预览、元数据
  analysis.py             LLM 工具调用与解释
  query.py                SQL 校验与受限执行
  schemas.py              Pydantic 请求/响应模型
backend/tests/
  test_demo.py            最小闭环与危险 SQL 拦截检查
datasets/

docs/
  demo-design.md
```

## 5. 接口约定

| 接口 | 请求 | 返回 |
| --- | --- | --- |
| `GET /api/health` | 无 | 服务状态、是否配置模型；不返回密钥 |
| `POST /api/datasets` | multipart 文件 | 数据集描述 |
| `POST /api/datasets/sample` | 无 | 导入内置 sales.csv 并返回数据集描述 |
| `GET /api/datasets/{id}` | 无 | 数据集描述与预览 |
| `POST /api/analyses` | `{dataset_id, question}` | 完整分析结果 |

数据集描述包含 `id`、`name`、`sheet_name`、`row_count`、`columns: [{name, type, null_count}]`、`preview: {columns, rows}`。使用后端生成的 ID 查找文件，绝不把用户传来的字符串当作路径。

分析响应示例（数值须由实际查询填入）：

```json
{
  "dataset_id": "<server-generated-id>",
  "question": "哪个地区销售额最高？",
  "answer": "华东地区销售额最高，合计 128 万元。",
  "sql": "SELECT region, SUM(sales) AS total_sales FROM data GROUP BY region ORDER BY total_sales DESC",
  "result": {
    "columns": ["region", "total_sales"],
    "rows": [["华东", 1280000], ["华南", 980000], ["华北", 750000], ["西南", 620000]]
  },
  "chart": {
    "type": "bar",
    "title": "各地区销售额",
    "x_field": "region",
    "y_field": "total_sales",
    "unit": "元"
  },
  "warnings": [],
  "execution_ms": 320,
  "mode": "llm"
}
```

ChartSpec 引用结果列，不重复传一份图表数值。前端统一渲染；不接受模型输出可执行 JavaScript 或 ECharts formatter 代码。折线图要求横轴具有有效时间顺序；不适合绘图的结果返回 `chart: null`。

错误响应统一为 `{error: {code, message}}`。区分格式不支持、空文件、字段缺失、数据集不存在、无效 SQL、查询超时和模型不可用。空查询结果属于正常响应，不编造结论。结果超过 500 行要明确提示并避免基于截断结果给出总体结论。

## 6. 必须在首版实现的保护

- 上传阶段限制原文件和 XLSX 解压后体积，并限制实际行列数；拒绝空表、重复/空列名及无法解析的数据，返回可操作提示。
- 原文件使用服务器生成名称保存；数据集物理隔离。保留原始数据，不用自动填零掩盖缺失值。
- SQL 不能只靠“以 SELECT 开头”判断安全。验证单条查询并限定 data 表，禁止写入、系统库、文件读取和耗时函数；应用只使用普通 MySQL 用户，并为查询设置执行时间限制。
- SQL 校验和 MySQL 查询限制需依据实际安装版本验证，并测试绕过输入。不要在没有这些措施时执行模型生成的任意 SQL。
- 前端不存密钥；后端通过环境变量读取，日志不输出密钥。模型输出按文本渲染，不直接插入 HTML。
- 上传文件及单元格里的指令均属于数据，不作为系统指令执行；工具只能使用后端认可的数据集。
- 首版服务仅监听本机，不默认向公网开放。

## 7. 三分钟演示脚本

使用合成的 sales.csv：2026 年 1—6 月、4 个地区，共 24 行；字段为 month、region、sales、orders，sales 单位为元。设计数据时让华东合计 1,280,000 元，其余地区分别为 980,000 / 750,000 / 620,000 元，总销售额为 3,630,000 元。

| 时间 | 操作 | 评委看到的证据 |
| --- | --- | --- |
| 0:00–0:30 | 上传示例文件并展开预览 | 确实读取了用户数据，展示字段和规模 |
| 0:30–1:20 | 问“哪个地区销售额最高？按销售额排序展示各地区” | 真实聚合结果、柱状图、最高地区结论 |
| 1:20–2:00 | 问“2026 年每个月的总销售额趋势如何？” | 按月份排序的折线图，数值与查询结果一致 |
| 2:00–2:30 | 展开 SQL 与结果表 | 展示结论的计算依据 |
| 2:30–3:00 | 问“按客户年龄统计销售额” | 说明缺少年龄字段，不虚构数据 |

备用模式：外部模型连接失败时，使用明确标记的预设 SQL 查询验证数据引擎与图表链路；答辩时如实区分 AI 模式与预设演示模式。

## 8. 开发顺序与验收

1. 数据链路：上传 → 校验 → MySQL → 预览；准备合成数据及独立可核对的预期总额。
2. 查询链路：先用固定 SQL 跑通结果表和图表，同时完成 SQL 执行限制。
3. AI 链路：配置模型 → 真实工具调用 → 执行 → 解读；无密钥与超时均有明确提示。
4. 工作台：接入上传、提问、结果卡片、空状态及错误状态。
5. 一次端到端验证：CSV 与 XLSX、地区排名、月度趋势、缺字段、空文件、危险 SQL、模型不可用。

完成标准：新成员按 README 能启动；上传后可提问；图表、结果表和回答数字一致；华东合计为 1,280,000 元且总额为 3,630,000 元；月度汇总之和等于总额；缺字段不编造；危险查询被拒绝；密钥不出现在浏览器或仓库。

Demo 验收后再由三人分工：A 负责前端交互与图表；B 负责问题理解、工具调用与解释；C 负责数据导入、查询安全与分析能力。三人先共同核对 `dataset`、`analysis`、`ChartSpec` 契约，之后各自优化。
